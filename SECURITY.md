# Security

## Secret Handling

Do not commit API keys, cloud credentials, browser cookies, private endpoints, or local `.env` files. Use environment variables or a private `.env` file copied from `.env.example`.

The previously exposed credentials must be revoked and rotated in their provider consoles before any public release:

- Browserless token
- OpenAI/Azure OpenAI keys and endpoints
- Tencent Cloud COS secret ID and secret key
- Google Search API key and CSE credentials
- ModelScope or other evaluation API keys
- Any Git credentials embedded in remotes
- Browser cookies or session tokens

Removing secrets from the working tree does not revoke them. Removing commit history does not revoke them either.

## Running Untrusted Tasks

The agent can execute Python code generated by a model. Run it in a container, VM, or equivalent sandbox with no access to production credentials, SSH keys, browser profiles, or sensitive local files.

## Public Release Checklist

Before publishing:

1. Rotate all exposed credentials.
2. Publish from a sanitized repository with no sensitive history.
3. Run a dedicated scanner such as `gitleaks` or `trufflehog`.
4. Verify `.env`, cookies, datasets, outputs, logs, `node_modules`, and `__pycache__` are absent from the release.
